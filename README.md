# 🛒 Rossmann Forecast — Прогнозно-аналитическая система управления спросом в розничной сети

## 📌 О проекте

Проект разрабатывается в рамках дисциплины «Прогнозно-аналитические системы» для профиля подготовки **«Управление данными»**.

Система обеспечивает полный цикл работы с данными: от автоматизированного сбора из разнородных источников до формирования прогноза и представления результатов в виде интерактивных дашбордов. Особое внимание уделено управлению жизненным циклом данных: качеству, историзации, прослеживаемости происхождения (lineage), устойчивости конвейера к сбоям и повторным запускам.

## 🎯 Предметная область и постановка задачи

### Предметная область
**Розничная торговля (продуктовый / ритейл)** на примере сети магазинов Rossmann.

### Бизнес-проблема
Розничные сети ежедневно сталкиваются с двумя рисками:
- **Out-of-stock** — отсутствие товара на полке → упущенная выручка;
- **Overstock** — избыточные запасы → рост списаний и заморозка оборотных средств.

Для сети из 1115 магазинов ручное планирование заказов неэффективно. Требуется автоматизированная система, которая на основе исторических продаж, внешних факторов (погода, промо-акции, конкуренция) формирует прогноз спроса.

### Прогнозируемый показатель
**Суточный объём продаж (`Sales`, в евро) в разрезе магазина (`Store`) на горизонте 6 недель.**

### Целевые пользователи
| Пользователь | Дашборд | Решаемая задача |
|---|---|---|
| Операционный директор сети | Предметный | Оценка прогноза продаж по регионам и форматам магазинов, выявление рисков |
| Дежурный аналитик / Data Engineer | Операционный | Мониторинг здоровья конвейера данных: статусы загрузок, качество данных, latency потока |

## 📥 Источники данных

В системе используется **3 разнородных источника**, различающихся по способу получения и формату представления (требование методички §3).

### Источник №1 — Исторические продажи (Batch, CSV)
- **Что:** Ежедневные продажи по 1115 магазинам сети Rossmann за 2013–2015 гг. (~1 млн строк).
- **Формат:** CSV, ~50 МБ.
- **Частота:** однократная начальная загрузка + инкрементальное обновление.
- **Откуда:** публичное соревнование [Kaggle — Rossmann Store Sales](https://www.kaggle.com/competitions/rossmann-store-sales/data).
- **Обоснование выбора:** достаточный объём исторических данных, наличие временной компоненты, публичная доступность.

### Источник №2 — Погода (API, JSON)
- **Что:** Ежедневные метео-данные (средняя температура, осадки) по координатам каждого магазина.
- **Формат:** JSON (ответ REST API).
- **Частота:** раз в сутки, инкрементально.
- **Откуда:** [Open-Meteo API](https://open-meteo.com/) — бесплатный, без ключа, открытый.
- **Обоснование:** погода — известный драйвер спроса в ритейле (жара → рост продаж напитков, дождь → снижение трафика).

### Источник №3 — Поток транзакций текущего дня (Stream, JSON)
- **Что:** Синтетический поток событий «пробития чека» в реальном времени.
- **Формат:** JSON-события (`event_id`, `store_id`, `sku_id`, `timestamp`, `qty`, `amount`).
- **Частота:** непрерывный поток.
- **Откуда:** генерируется Python-скриптом (`ingestion/streaming/generator.py`) на основе исторических паттернов из `train.csv` и публикуется в **Redpanda** (Kafka-compatible).
- **Обоснование:** закрывает требование методички о наличии потоковых данных и позволяет реализовать **операционный дашборд** (факт vs план в реальном времени).

> ⚠️ Все источники являются **общедоступными либо синтетически сгенерированными**. Персональные данные не используются (требование методички §5.4).

### Оркестрация
Все процессы управляются **Apache Airflow** через DAG-и с расписанием, retry-политикой и идемпотентностью.

## 🛠 Технологический стек и обоснование

| Компонент | Технология | Обоснование |
|---|---|---|
| Хранение | **PostgreSQL 15** | Транзакционность, CHECK-констрейнты для DQ на уровне БД, JSONB для сырых данных, оконные функции для SCD |
| Оркестрация | **Apache Airflow 2.8** | DAG-и, идемпотентность, retry, журнал запусков, расписание |
| Трансформации | **dbt-core** | SQL-модели для слоёв Silver/Gold, автоматические тесты качества |
| Потоковые данные | **Redpanda** | Kafka-compatible, без Zookeeper, легковесный для локального развёртывания |
| BI-визуализация | **Apache Superset** | Open-source, прямое подключение к PostgreSQL |
| Качество данных | **dbt tests + Great Expectations** | Проверки полноты, уникальности, допустимости, диапазонов |
| Контейнеризация | **Docker Compose + Make** | Воспроизводимость, запуск одной командой |
| Конфигурация | **.env + YAML** | Конфигурируемость (требование §5.3) |

## 🚀 Быстрый старт (воспроизводимость)

### Предварительные требования
- Docker Desktop (или Docker Engine + Docker Compose v2)
- GNU Make
- ~4 ГБ свободной оперативной памяти

### Установка и запуск

```bash
# 1. Клонировать репозиторий
git clone <repo-url> && cd rossmann-forecast

# 2. Скачать исходные данные (открытые, без персональных данных)
mkdir -p data/raw
curl -o data/raw/train.csv  https://raw.githubusercontent.com/jbencook/rossmann-store-sales/master/data/train.csv
curl -o data/raw/store.csv  https://raw.githubusercontent.com/jbencook/rossmann-store-sales/master/data/store.csv
curl -o data/raw/test.csv   https://raw.githubusercontent.com/jbencook/rossmann-store-sales/master/data/test.csv

# 3. Поднять всю инфраструктуру одной командой
make up

# 4. Инициализировать Airflow (только при первом запуске)
make init-airflow

# 5. Проверить, что все схемы БД созданы
make init-db
```

### Доступы к сервисам

| Сервис | URL | Логин / Пароль |
|---|---|---|
| Airflow UI | http://localhost:8080 | `admin` / `admin` |
| PostgreSQL | `localhost:5432` | `rossmann_user` / `rossmann_password` |
| Apache Superset | http://localhost:8088 | `admin` / `admin` |
| Redpanda (Kafka) | `localhost:9092` | — |

### Остановка

```bash
make down    # остановить контейнеры (данные в volumes сохраняются)
```
